# Poymai Deploy 3.1

Трей-приложение (Windows + macOS) для деплоя PoymAI и Telegram-шлюза.

**Модель:** GitHub `main` — единственный источник правды.
Деплой = коммит → push в GitHub → сервер ставит *ровно этот коммит*
(`scripts/deploy/remote-deploy.sh` в каждом проекте) → проверка здоровья →
при ошибке автоматический откат → ветка `production` и тег `deploy/*` в GitHub.
Второй компьютер каждые 60 с видит новый коммит и сам подтягивает его
(если есть локальные правки — спрашивает).

## Связь с сайтом (PoymAI)
Приложение по SSH запускает внутри контейнера backend
`python3 -m app.deploy_window` (команда настраивается в «Настройках»). Проба
обращается к API на loopback контейнера с ключом, производным от JWT-секрета, —
пароль от админки не нужен и снаружи ничего нового не открыто. Что видно:

- **Готовность сайта**: «Можно деплоить» / «Можно, но кое-кто заметит» /
  «Лучше подождать» с причинами (кто работает сейчас, импорты, отложенные
  сообщения, оплаты, поток сообщений). Люди «вне статистики» не учитываются.
- Ближайшие 24 часа по нагрузке и лучшие окна для деплоя.
- **Баннер пользователям**: «Обновление через N мин» в панели у всех клиентов.

Перед ручным деплоем, если сайт говорит «подождать», приложение предлагает
задеплоить в тихое окно, предупредить и через 5 минут или всё равно сейчас.

## Расписание
- **Ко времени** — деплой в заданный момент (с баннером за N минут).
- **Когда никого нет** — приложение раз в минуту спрашивает сайт и деплоит,
  как только «можно» (опционально: «кое-кто заметит» тоже подходит; крайний срок,
  после которого — деплой всё равно или отмена).
- **Через N минут** — баннер сразу, деплой по истечении.

Изменения коммитятся и пушатся в момент планирования, поэтому позже
ставится ровно этот коммит. Задания хранятся в `~/.poymai-deploy/schedule.json`
и переживают перезапуск; приложение должно быть запущено (живёт в трее).

## «Что уедет»
Коммиты и файлы между `production` и локальной копией, сгруппированные по
областям, с предупреждениями: миграции БД (будет бэкап), зависимости/Docker
(долгая сборка), nginx, сам скрипт деплоя.

## Установка
- Windows: `src-tauri/target/release/bundle/nsis/Poymai Deploy_*_x64-setup.exe`
- Mac: см. [MAC_SETUP.md](MAC_SETUP.md) — 4 команды, всё остальное делает `install-mac.sh`.

На каждом компьютере нужен SSH-ключ `~/.ssh/id_ed25519_poymai`, добавленный
на `poymai@192.168.3.209` и `root@192.168.3.99`.

Настройки компьютера: `~/.poymai-deploy/config.json` (пути к проектам, маршруты:
LAN → внешний `185.33.228.250` → шлюз через ProxyJump).

## CLI
```
poymai-deploy deploy main -m "сообщение"
poymai-deploy deploy telegram --dry-run
poymai-deploy deploy main --sha <commit>     # откат / передеплой
poymai-deploy window                         # можно ли деплоить сейчас (код 0 / 3 / 4)
```

## Разработка
```
npm ci
npx tauri dev
```
`server/remote-deploy.sh` — эталон серверного скрипта; копия лежит в
`scripts/deploy/` каждого проекта вместе с `deploy.conf`.
`legacy/` — старое Python-приложение.
